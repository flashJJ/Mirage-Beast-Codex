# 战斗平衡分析（首份量化报告）

> **日期**：2026-10-06
> **范围**：V0 战斗核心 + 可玩 UI 的默认对局
> **工具**：`tests/balance.gd`（新增）、`tests/simulate.gd`（已有）
> **复现**：`godot --headless --script res://tests/balance.gd --runs 400`

---

## 0. 一句话结论

**规则层没有 bug，但数值曲线太陡**：敌方等级从 Lv7 提到 Lv8（全部属性只涨约 8%），我方胜率从 **87.0% 直接崩到 38.3%**。
这说明当前伤害模型对「双方战力接近」极度敏感，后续做内容难度阶梯时会很难调 —— **这是必须先解决的结构问题，不是调几个数字能糊过去的**。

已顺带修掉两个只在 UI 层暴露的真 bug（第 4 节）。

## 1. 度量方法

| 项 | 做法 |
|---|---|
| 代理玩家 | 双方都用 `SimpleAI("easy")` 驱动（含 20% 概率主动失误） |
| 样本量 | 每组 400 局，种子固定 `1000 + i`，结果可复现 |
| 指标 | 胜率 / 平局率 / 平均回合数 / **结束方式分布** / 终局存活数 |
| 目标区间 | **60% ~ 85%**（第一场战斗应该"能赢但要动脑子"） |

**重要偏差声明**：`SimpleAI("easy")` 有 20% 主动失误率，且 UI 里我方**恒先手**。
因此真实人类玩家的胜率会**高于**本报告数值。调难度时应以本报告数值为**下界**。

## 3. 发现的问题（按严重度）

### 🔴 P1 · 等级悬崖：1 个等级 = 49 个百分点胜率

Lv7→Lv8 只带来约 8% 的属性增长，胜率却掉 49 点。

**根因（结构性，不是数值问题）**：

1. **伤害是「减防」模型**：`DMG = ATK×倍率 − DEF×0.45`。
   防御是**固定减算**，所以在攻防接近的区间，攻击力每涨一点都会成倍放大净伤害；
   一旦越过阈值，就从"互相打不动"变成"两下秒一个"，中间没有过渡带。
2. **雪球效应没有阻尼**：单位倒下后该方输出直接掉 1/3，而治疗/护盾的回复量是按施法者属性算的固定值，
   无法随局势放大。领先方会越滚越大。
3. **先手恒定**：V0 我方恒先手，这本身是隐性优势，也放大了"谁先手谁赢"的二元性。

**候选解法（待评估，不在本文档拍板）**：

| 方案 | 说明 | 代价 |
|---|---|---|
| S1 防御改乘性减伤 | `DMG = base × 1000/(1000 + DEF×k)`，天然有平滑过渡 | 需重算全部数值，改 `damage_calc.gd` |
| S2 提高治疗/护盾的局势响应 | 低血量时治疗量加成（如 ×1.5） | 引入新原语或新字段，需扩 schema |
| S3 拉长战斗（提高 HP 或降低倍率） | 让单局回合数增加，摊薄单次优势 | 战斗变慢，与"卡牌节奏"冲突 |

**建议**：先做 S1，它是唯一从根上降低敏感度的方案；S2/S3 是补丁。

### 🟡 P2 · 控制类技能强度异常 —— **规则缺口已修（F42）**

候选 E 把影爪猫换成**藤蔓熊**后胜率掉到 46.0%，而藤蔓熊的面板（atk 14）并不比影爪猫（atk 14）高。
差距来自「藤蔓嘲讽」：`TAUNT` 全场 + `DEBUFF atk ×0.85` 全场，每回合可重复施加。

⚠️ **同时发现一个规则缺口**：`EffectSystem.pick_targets()` **完全没有处理嘲讽**——
`taunted_by` / `taunt_turns` 写进了单位字典，但选目标时没人读它。
也就是说嘲讽当时**只在数值上生效（DEBUFF 部分），控制效果（强制选目标）是失效的**。
这既解释了 E 的强度来源（纯 DEBUFF 叠加），也意味着带嘲讽的卡全是"半成品"。

**已修复（F42）**：新增 `EffectSystem.taunt_source()` + `ATTACK_OPS` 白名单。

| 规则 | 说明 |
|---|---|
| 受约束的原语 | `DAMAGE` / `DEBUFF` / `TAUNT`（"打出去"的） |
| 不受约束的原语 | `HEAL` / `SHIELD` / `BUFF` / `PURIFY` / `DRAW` / `ENERGY` |
| 约束失效条件 | 嘲讽者阵亡 / 嘲讽持续回合归零 / 同阵营 / 被净化 |

> 关键点：**治疗类效果绝不能被嘲讽重定向**，否则会出现「被嘲讽后只能给敌人加血」的荒谬结果。
> 普攻（`TurnMachine.basic_attack`）同样走这条约束，否则只有被动技能的单位不受嘲讽影响。

修复后重跑全部套件：规则单测 44 项、UI 冒烟 38 项、平衡基线与遭遇战胜率均无回归。
**注意**：候选 E（藤蔓熊）的 46.0% 是在嘲讽失效状态下测的，修复后需重测。

### 🟡 P3 · 超时判定占比 17.3%

不算高，但意味着约 1/6 的对局是"谁也没打死谁"。若 P1 按 S3 方向调整会让这个比例恶化，需监控。

### 🟢 P4 · 我方阵容里 2/3 的单位没有输出手段

焰尾狐（双尾连击）是唯一有伤害主动技的；潮汐龟只有 `on_play` 护盾，木灵鹿只有治疗。
**这不是 bug，是配队问题**，但它放大了 P1：我方实际 DPS 只有敌方的约一半。

| # | 现象 | 根因 | 修复 |

> **这就是"UI 冒烟测试必须存在"的理由**：`tests/test_ui.gd` 用代码模拟点击，覆盖这条链路。

## 8. 第二轮：等级悬崖的真正根因（2026-10-06 晚）

**结论先行：P1「等级悬崖」的根因不是减伤模型，是「先手优势过大 + 阵容不公平」。**

### 8.1 实验设计

新增 `tests/diag_cliff.gd`，用三组对照把三个可能因素分开：
1. **镜像对局**：双方阵容与等级完全相同 → 理论胜率应为 50%（偏差即系统性问题）
2. **换边对照**：同一组对局交换先后手 → 两边胜率之和应 ≈100%（偏离即先后手偏差）
3. **等级差扫描**：我方固定 Lv8，敌方 Lv6~Lv10

### 8.2 结果（改乘性减伤**之后**，每组 400 局）

| 实验 | 结果 | 解读 |
|---|---|---|
| 熔岩队镜像 Lv8 | **先手方 98.3%**，平均 4.4 回合 | 🔴 先手方几乎必胜，一轮爆发直接锁定胜负 |
| 焰尾狐队镜像 Lv8 | 先手方 37.5%，平均 10.5 回合 | 🔴 低输出阵容反而先手吃亏（先手先吃牌库疲劳） |
| A vs B 换边互补性 | 132%（应 100%） | 🔴 先后手偏差约 30~48 个百分点 |

**为什么减伤模型改了却没用**：伤害模型只决定"每一下打多少"，
而这里的胜负是由「能否在第一轮建立击杀 → 3v3 变 3v2 → 雪球」决定的。
战斗呈现两个极端：**4 回合爆发秒杀** 或 **10+ 回合拖到疲劳判定**，没有中间地带。
属性略微变化就切换模式，这才是曲线陡峭的来源。

### 8.3 已实施的修复

| # | 措施 | 效果 |
|---|---|---|
| **F43** | 减伤改**乘性** `DMG = base × 1000/(1000+DEF×5.8)`（`DEF_FACTOR` 450→5800） | 曲线平滑、无阈值、无负伤害；但**单独不足以解决悬崖** |
| **F45** | **后手补偿**：后手多抽 1 张 + 多 1 点费用（经典"硬币"机制） | 熔岩队镜像 98.3% → **68.5%**（Lv8），先手偏差显著收窄 |

新增 8 项公式回归断言（`test_battle.gd::test_multiplicative_defense`），
把"减伤必须是乘性的"这个决策钉死——谁改回固定减算，测试立刻红。

### 8.4 残留问题（下一轮）

| # | 现象 | 待办 |
|---|---|---|
| R1 | 熔岩队镜像 Lv10 仍有 82%（先手偏差 32 pt） | 高等级爆发仍偏强，考虑提高 HP 或削单体倍率 |
| R2 | 焰尾狐队镜像恒为 -10 pt | **先手方先抽牌 → 先耗空牌库 → 先吃疲劳**，超时判定按血量故先手吃亏 |
| R3 | 遭遇战"熔岩獠牙"胜率 66.5% → 45.5% | 后手补偿让敌方变强，需按新基线重调 `data/encounters.json` |
| R4 | P4 阵容不公平未解决（我方 3 只里 2 只无输出手段） | 属配队数据问题，改 `data/cards.json` 或默认阵容 |

### 8.5 关键教训

> **"等级悬崖"是一个症状，不是诊断。** 第一次看到 Lv7→Lv8 掉 49 个百分点时，
> 直觉归因于"减伤模型太陡"，改完模型掉幅只从 49 变 49——因为真正的变量根本没被碰到。
> 必须先用**镜像/换边对照实验**分离"模型""先后手""阵容"三个因素，再动手改。
